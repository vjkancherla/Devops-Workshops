Packer + Ansible + Terraform + Jenkins
+ Monitoring server (with Prometheus + Grafana and ElasticSearch + Kibana)
-----------------------------------------------

In this project we will:
1. create an AMI using PACKER, called monitoring-ami, with the following software:
-- Prometheus [port 9090]
-- Grafana [port 3000]
-- ElasticSearch [port 9200]
-- Kibana [port 5601]
-- Filebeat
-- Metricbeat
-- Prometheus Node Exporter [port 9113]
PACKER (Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/Packer/monitoring) uses ANSIBLE (Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/Ansible/monitoring) as the provisioner
Note: all the above pieces of software will be listening on localhost

2. create an EC2 instance, called monitoring-instance, (+ CLB), using the AMI from step-1, using TERRAFORM (Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/Terraform/layers/monitoring).
Also, along with the monitoring-instance, TF also create the following R53 resources:
-- project8.local
-- elasticsearch.project8.local
-- grafana.project8.local
-- kibana.project8.local
-- prometheus.project8.local
-- monitoring.project8.local
all the above records point to the private IP of monitoring-instance

3. run AWS SSM CLI command, against the monitoring-instance, to update the config files, of the below pieces
of softwares, to use the R53 record-Sets
-- Prometheus
-- Grafana
-- ElasticSearch
-- Kibana
-- Filebeat
-- Metricbeat
The AWS SSM CLI command will run a shell script on the monitoring-instance, which in-turn, downloads and
runs an ansible playbook (Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/Ansible/monitoring-standalone)

NOTE::: the reason for the need of step-3 is that:
Goal: we want all our monitoring software's endpoints to be resolved from the while AWS env,
we will want to use R53 record sets
==> in step-1, the AMI will be created with all the monitoring software config pointing to localhost.
This is because, the very first time, the R53 record sets will not exist. So, if we were to try to
configure the monitoring software's endpoints to use R53 record sets, Ansible play-book (privision-monitoring.yml)
will fail, resulting in Packer aborting the AMI creation
==> step-2 creates the R53 record sets and will associate the private-ip of the monitoring instance with
the record sets
==> now that we have the R53 record sets, we need to update the  monitoring softwares' config files to
use the record sets, instead of localhost. We do this using SSM CLI 


4. create an AMI using PACKER, called jenkins-ami. Again, PACKER (Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/Packer/jenkins) uses ANSIBLE (Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/Ansible/jenkins) as the provisioner

5. create an EC2 instance, called jenkins-instance, (+ CLB), using the AMI from step-4, using TERRAFORM

=========================
STEPS 1-5 are triggered by running the following shell script:

Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/entry-point/start.sh

1. Install Packer locally

2. Use packer, with Ansible provisioner, to build a the Monitoring AMI.

3. Use Terraform to create the Monitoring Env + R53 private hosted zone (project8.local)
--- note, use Ansible provisioner to do some extra config

2. Use packer, with Ansible provisioner, to build a Jenkins AMI and Monitoring AMI.
And then, create the Jenkins Infra and Monitoring Infra, using Terraform, with the AMIs
>> Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/entry-point/start.sh

NOTE: If you are on the Rackspace VPN or SDP solutions (assumed default), direct outbound SSH will be blocked
and the bastions must be used. Since the Packer SSH client does not play nicely with our bastions via the
packer native bastion_* configuration directives, a workaround must be used:
>> In a separate terminal to the one you are using for you packer build, SSH to your local Rackspace bastion
directly while enabling SSH agent forwarding and enabling local dynamic application-level port forwarding,
e.g: ssh -AD 1337 bastion


3. login to Jenkins and create a pipeline job called "WP-pipeline" and use the below Jenkins file:
Project-8/Pk_An_Tf_Jk_Wp_Pr_Gr_Elk/Jenkins-Pipeline/jenkinsfile.groovy

The pipeline expects two parameters to be passed in.
You can override the default values by click "build with parameters"
